# Format

A.T, the Agentic Terminal: a chat and agent workspace on the Claude API with claude.ai's layout and flow, in the form family's Studio Dark design. Vanilla TypeScript and Vite frontend, Python and FastAPI engine, a Rust crate on wgpu where needed, and a Tauri 2 desktop shell (from v0.11.0) in `src-tauri/` that runs the engine frozen by PyInstaller (`backend/format_engine.py`, `setup/freeze_backend`) as a sidecar; see `.docs/wiki/Desktop.md`.

## Repo layout notes

- The engine owns all state. Every action is a command registered with `@command` in `backend/app/engine/cmd_*.py` and dispatched the same way by the window (`POST /api/commands/{id}`), the CLI (`./format cli <id> key=value`) and, from v0.7.0, the MCP server. Changes publish events on `/api/events` (WebSocket); the window patches what changed.
- `frontend/src/styles/` holds the family's vendored Studio Dark sheets unchanged (`tokens.css`, `scrollbars.css`, `fonts.css`, `shell.css`, `dialogs.css`, `light-mode.css`) beside Format's own `ft-*.css` (`ft-` classes). Colours and z-index come from tokens only.
- `native/format-render` is the family-standard wgpu crate (`Gpu`, `budget`, opt-in `native_start` on FORMAT_NATIVE): a terminal glyph grid (vt100 screen, fontdue atlas, one full-screen shader) with a CLI binary (`info`, `snapshot`) and a winit demo window behind the `window` feature. The engine calls the binary from `backend/app/engine/native.py` (`native.status`, `terminal.snapshot`); nothing runs while FORMAT_NATIVE is unset, and the window's terminal stays xterm.
- `backend/app/harness/` is the only place a Claude API request is built (system prompt, content blocks, effort, thinking, caching); `backend/app/providers/` holds one adapter per provider. Chat runs through `chat.send`, `chat.stop`, `chat.retry`, `chat.edit`, `chat.branch`, `chat.compact` and `chat.wait`; a stored compaction block (beta `compact-2026-09-04`) starts every later request, and attachments of 1 MB or more go through the Files API; keys through `keys.set`, `keys.clear`, `keys.status`. A chat is a tree of messages (`parent_id`) with `conversations.leaf_id` marking the path on screen; `messages_of` returns that path.
- Tools live in `backend/app/engine/tools.py` (definitions, the per-chat folder `workspace/chats/<id>`, approvals, executors); the loop is `chat._run`, which keeps a whole multi-round reply in one message with `tool_result` blocks inline and lets `harness.api_messages` split it for the API. Approvals: `tool.approve`, `tool.pending`; questions: `tool.answer`; the plan and the files Claude sends: `tasks.get`, `outputs.list`, downloads under `/api/chats/{id}/`. Sub-agents (`spawn_agent`) run inside the parent's tool call (`chat._run_agent`) and keep their transcript in `meta.agents`. Artifacts (`publish_artifact`, `backend/app/engine/artifacts.py`) are versioned rows served at `/api/artifacts/{id}/v/{n}` under a sandboxing CSP; the window shows them in `frontend/src/ui/artifact-panel.ts`, never with `allow-same-origin`. The chat folder's files come through `files.list` and `files.read` and preview in `frontend/src/ui/files-pane.ts`, which shares the side track with the artifact panel (`data-ft-side`); comments on them travel in `chat.send` `comments`. Projects (`backend/app/engine/projects.py`, `cmd_project.py`) hold instructions and knowledge files (uploads); `projects.context` is read at the start of each reply, and `harness.build` puts the instructions in the system prompt and the files at the start of the first user turn. Memory (`memory.py`) runs Anthropic's client-side memory tool on `data/memory` (general or per project); skills (`skills.py`) are SKILL.md folders in `data/skills`, listed in the system prompt and loaded through the `skill` tool. Connectors (`connectors.py`) send public https MCP servers through the API's MCP connector (`mcp_servers`, `mcp_toolset`, beta `mcp-client-2025-11-20`) and run every other server in the engine with the `mcp` SDK, as client tools named `mcp__<connector>__<tool>` that go through approvals. Format is itself an MCP server (`backend/app/mcp_server.py`, generated from the command registry: a tool per command with `.` as `_`, plus `run_command`, chat and artifact resources, three prompts), served at `/mcp` (`routers/mcp_http.py`, Streamable HTTP) and over stdio by `./format mcp` (`mcp_stdio.py`, a proxy to the running engine's REST API with header `x-format-agent`). Outside agents pass `agents.require` (setting `outsideAgents`: ask, allowed, blocked; ask publishes `agents.consent` and waits for the window). Scheduled tasks (`backend/app/engine/schedules.py`, tables `schedules` and `schedule_runs`, schema 7) run on a scheduler thread started with the engine; each run is `chat.send` into a new chat, and `background.list` reports every chat working or waiting. Documents, spreadsheets and decks are artifact kinds written by `write_document` and exported by `documents.py`. Other devices (`backend/app/engine/devices.py`) run a second, cookie-gated server on port 8492 only while the person turns it on; share links (`artifact.share`, table `shares`, schema 8) are served at `/s/{token}`. Plugins (`plugins.py`) install a Claude plugin folder's skills, commands and MCP servers as Format skills and connectors and track them in `data/plugins/<name>/.format-plugin.json`. The built-in browser (`browser.py`, optional Playwright) runs on one worker thread; Claude's `browser` tool and the window's Browser pane (`frontend/src/ui/browser-pane.ts`) drive the same page.
- Terminals are engine PTYs (`backend/app/engine/terminal.py`): the window's dock attaches over `WS /api/terminal/{id}`, and `terminal.write` and `terminal.read` let the CLI and agents use the same shells. Claude's own bash commands are mirrored into one read-only session of kind `agent` (no PTY), shown as the Claude tab. Layout state (sidebar, panel, terminal) lives on `documentElement` data attributes set before first paint.
- The manual for people using Format is `docs/`; the developer wiki is `.docs/wiki` (architecture, engine, window, agents, checks, releasing); `BRANCHING.md` covers branches and tags. Update the manual page a change shows on.
- Planning documents (DEV_PLAN, BUILD_NOTES, UI_STUDY, PARITY_BASELINE, the root HASHOUT_LOG) ship in the planning sidecar zip, not in this tree. The living logs `frontend/HASHOUT_LOG.md` and `backend/HASHOUT_LOG.md` are in the tree: read them before editing.
- On Windows the launcher is `.\format.bat`; a bare `format` outside the repo is the system disk formatter.

## Skills

`.claude/skills/format-harness/` is the orchestrator for changing and releasing Format: load its `SKILL.md` for any code change; it routes to twelve specialists and holds the completion gate. `.claude/skills/format-driving/` is for using a running Format over MCP. `./format agents sync` regenerates their tool and command references from the registry and mirrors both into `.agents/skills/`; run it whenever a command is added, renamed or re-described, after adding it to `GUIDE` in `backend/app/agent_guide.py` (its MCP tool name and a "Use when" sentence).

## Laws

Single-region hand edits only (no sed, patch, git apply or scripted edits), zero DOM flash or re-render (verify under 4x CPU and slow network), no visible scrollbars anywhere, no emoji, no em dash in markdown, no icon-library dependencies, z-index only through tokens, near-zero comments with rationale in the HASHOUT logs, `v*.*.*` versions, Conventional Commits as `nodemode-ai <mackin@nodemode.ai>`.
