# Format tools

Generated by ./format agents sync from the engine's command registry; do not edit by hand, run the sync again after changing a command.

Every tool is one engine command. Read-only tools change nothing; for the others the window shows the change live. A parameter with ? is optional. Pass ids from earlier results rather than guessing them.

## Chat with Claude

### switch_branch

Switches the chat to another version of an edited message and the newest conversation that follows it. Returns the messages on the new path. Use when the person wants to go back to another version of an edited message.

- changes state · command `chat.branch` · params: `conversationId` string, `messageId` string

### compact_chat

Asks Claude to summarize the chat so far (the API's compaction). The summary is kept as a message on the path and later turns start from it instead of the full history; the earlier messages stay visible. Runs like a reply: chat.wait waits for it. Also runs on its own after a reply once the chat passes compactAt of the context window, unless autoCompact is off. Use when a long chat is near its context limit and should continue from a summary.

- changes state · command `chat.compact` · params: `conversationId` string

### edit_message

Adds the edited text as a new version of one of the person's messages (keeping its attachments) and asks again from there. The earlier version and everything after it stay as a branch; chat.branch switches between versions. Use when a message the person sent should be changed and answered again, keeping the old version as a branch.

- changes state · command `chat.edit` · params: `conversationId` string, `text` string, `messageId?` string

### retry_reply

Deletes the last reply (if it is Claude's) and asks again with the same history and current settings. Use when Claude's last reply failed or should be asked again unchanged.

- changes state · command `chat.retry` · params: `conversationId` string

### send_message

Stores the message (with its attachments and comments on the chat's files) and starts Claude's reply, which streams as message.delta events. Returns the chat id, the user message and the reply's id; read the finished reply with conversation.get or chat.wait. Use to ask Claude something in Format: omit conversationId to start a new chat, then call wait_for_reply with the conversationId it returns.

- changes state · command `chat.send` · params: `text` string, `conversationId?` string, `attachments?` array, `comments?` array, `projectId?` string, `title?` string, `research?` boolean, `output?` string

### stop_reply

Stops a running reply; what was written so far is kept. Use when a running reply should end now; what was written stays.

- changes state · command `chat.stop` · params: `conversationId` string

### wait_for_reply

Waits (up to timeout seconds, default 300) for the running reply to finish and returns the last message. For agents and the CLI. Use right after send_message, retry_reply or edit_message to get Claude's finished reply text.

- read-only · command `chat.wait` · params: `conversationId` string, `timeout?` number

## Chats

### allow_all_in_conversation

Turns Allow for this chat on or off. While on, every tool Claude uses in this conversation runs without an approval card, on the API and through Claude Code; Plan mode and the deny list still apply, and other chats keep the permission mode. Turning it on also allows the approvals already waiting in the chat. Use when the person wants every tool in one chat to run without approval cards, or to turn that off again.

- changes state · command `conversation.allowAll` · params: `id` string, `on` boolean

### create_conversation

Creates an empty conversation and returns it with its id. Use when you need an empty chat to publish into before anything is said; send_message without conversationId also creates one.

- changes state · command `conversation.create` · params: `title?` string, `projectId?` string

### delete_conversation

Deletes a conversation and its messages, and removes its attachments from the Anthropic Files API where they were uploaded. Not undoable. Use only when the person asks to delete a chat; it cannot be undone.

- changes state · command `conversation.delete` · params: `id` string

### get_conversation

One conversation and its messages in order. Use to read a chat's messages, tool steps and status by its id.

- read-only · command `conversation.get` · params: `id` string

### list_conversations

Lists conversations, pinned first, then most recently updated; query matches the title or the text of any message. Use to find a chat by title or by words in its messages, or to get recent chat ids.

- read-only · command `conversation.list` · params: `query?` string, `limit?` integer

### move_conversation

Puts a chat in a project, or takes it out; its next reply uses the project's instructions and files. Use when a chat should get a project's instructions and files, or leave its project.

- changes state · command `conversation.move` · params: `id` string, `projectId?` string

### pin_conversation

Pin chat Use when the person wants a chat kept at the top of the sidebar, or unpinned.

- changes state · command `conversation.pin` · params: `id` string, `pinned` boolean

### rename_conversation

Rename chat Use when a chat's title should change.

- changes state · command `conversation.rename` · params: `id` string, `title` string

### add_message

Appends a message to a conversation (role user by default). From v0.3.0 chat.send also asks the model for the reply. Use only to record a message without asking Claude; to get an answer use send_message.

- changes state · command `message.add` · params: `conversationId` string, `text` string, `role?` string, `parentId?` string

## Artifacts

### delete_artifact

Deletes an artifact and all its versions. Not undoable. Use only when the person asks to remove a page; it cannot be undone.

- changes state · command `artifact.delete` · params: `id` string

### export_artifact

Writes an artifact version as a file: a document as md, docx or pdf; a spreadsheet as csv or xlsx; slides as pptx, pdf or md; a page as html. Returns the file's path and a download URL. Use when the person wants a file: a document as Word, PDF or Markdown, a spreadsheet as Excel or CSV, slides as PowerPoint or PDF.

- changes state · command `artifact.export` · params: `id` string, `format` string, `version?` integer

### get_artifact

One artifact with its versions and the source of one version (the latest unless version is given), plus the URL the window shows it from. Use when you need a published page's HTML or its version list, for example before publishing a new version.

- read-only · command `artifact.get` · params: `id` string, `version?` integer

### list_artifacts

Artifacts Claude published, newest first, in one chat or all chats, with their title, chat, version count and latest version. Use when looking for a page published earlier, in one chat or across chats.

- read-only · command `artifact.list` · params: `conversationId?` string

### publish_artifact

Publishes an HTML page as an artifact of a chat, or a new version of one, the way Claude's publish_artifact tool does; it appears in the window's Artifacts page and, when that artifact is open, in its panel. For outside agents and scripts. Use when you want to show the person a page, app or document: it appears in that chat and on the Artifacts page; pass artifactId to add a version.

- changes state · command `artifact.publish` · params: `conversationId` string, `title?` string, `html` string, `artifactId?` string

### share_artifact

Makes a read-only link to an artifact (the latest version, or one pinned version). Anyone who can reach this computer's network listener can open it; start it with devices.start to share beyond this computer. Returns the link. Use when the person wants a read-only link to a page, document, sheet or deck for someone else.

- changes state · command `artifact.share` · params: `id` string, `version?` integer

### list_artifact_links

The artifact's share links, if any. Use to see whether an artifact is shared and its links.

- read-only · command `artifact.shares` · params: `id` string

### unshare_artifact

Revokes every link to the artifact at once; opening an old link shows that it is no longer shared. Use when the person wants a shared link to stop working.

- changes state · command `artifact.unshare` · params: `id` string

### write_document

Creates or revises a document, spreadsheet or slide deck in a chat, the way Claude's write_document tool does; each write is a new version shown live beside the chat. Returns the artifact with its id and version. Use to create or revise a document, spreadsheet or slide deck in a chat; pass section to change one part.

- changes state · command `artifact.write` · params: `conversationId` string, `kind?` string, `title?` string, `content` string, `artifactId?` string, `section?` string

## Chat files and outputs

### list_chat_files

Every file in the chat's own folder (the one Claude's tools work in), as paths relative to it with size, modified time and a preview kind: image, pdf, video, audio, markdown, html, code, zip or binary. Skips .git, node_modules and similar; at most 2000 files. Use to see the files Claude wrote or changed in a chat's own folder.

- read-only · command `files.list` · params: `conversationId` string

### read_chat_file

The text of one file in the chat's folder, up to 1 MB (longer files are cut and marked truncated), with its kind and size. Binary files are refused; use the file's URL for those. Use to read one file from a chat's folder, for example code Claude wrote there.

- read-only · command `files.read` · params: `conversationId` string, `path` string

### save_download

Saves one of the engine's own downloads (an artifact page, an export, a chat file, Download all) into the person's Downloads folder under the server's file name, numbered if taken, and returns where. The desktop app's window uses it for every download. Use to put an artifact page, an export or a chat's file into the person's Downloads folder.

- changes state · command `files.save_download` · params: `url` string, `reveal?` boolean

### list_outputs

Files Claude sent in this chat (send_file) with their download paths, and what was used in the session: uploads, web searches and fetches, commands, files changed. Use to get the files Claude handed over in a chat and their download paths.

- read-only · command `outputs.list` · params: `conversationId` string

### get_task_list

The chat's task list as Claude last set it with task_list: titles with pending, in_progress or completed. Use to see the plan Claude keeps for a chat and how far it got.

- read-only · command `tasks.get` · params: `conversationId` string

## Connectors

### add_connector

Adds an MCP server by URL or by command. A public https URL goes to Claude through Anthropic's MCP connector; a URL on this computer or a private network, and every command, is run by the engine, and its tools ask for approval like commands do. Then connector.connect lists its tools. Use when the person wants Claude in Format to reach another MCP server, by URL or by command.

- changes state · command `connector.add` · params: `name` string, `url?` string, `command?` string, `token?` string, `env?` object

### connect_connector

Connects to the server (starting it, for a command) and lists its tools; run it again to reconnect. Returns the connector with status connected or error. Use after add_connector, or when a connector shows an error, to (re)connect and list its tools.

- changes state · command `connector.connect` · params: `id` string

### delete_connector

Removes a connector and closes its connection. Use only when the person asks to remove a connector.

- changes state · command `connector.delete` · params: `id` string

### list_connectors

MCP servers added to Format: name, URL or command, route (api: sent to Anthropic's MCP connector; local: run by the engine), status, and their tools with on and off. Use to see which MCP servers Format's Claude can use and whether they are connected.

- read-only · command `connector.list` · params: none

### update_connector

Turns a connector on or off, sets which of its tools are off, or replaces its token. Use to turn a connector or some of its tools on or off, or to replace its token.

- changes state · command `connector.update` · params: `id` string, `enabled?` boolean, `disabledTools?` array, `token?` string

## Scheduled tasks

### list_schedules

### update_schedule

## Terminals

### get_native_status

Whether Format's native wgpu renderer is built and turned on (FORMAT_NATIVE=1), and the GPU adapter it uses. It draws terminal screens as images (terminal.snapshot); the window's own terminal stays in the browser. Use before snapshot_terminal, to see whether the native renderer is built and on.

- read-only · command `native.status` · params: none

### close_terminal

Ends the shell and closes the terminal. Use when a terminal you opened is no longer needed.

- changes state · command `terminal.close` · params: `id` string

### list_terminals

Open terminals with their ids, titles, folders and whether the shell is still running. kind is shell, or agent for the read-only Claude tab where every bash command Claude runs, and its output, appears live. Use to find terminal ids, including the read-only Claude tab.

- read-only · command `terminal.list` · params: none

### open_terminal

Starts the person's login shell in a real terminal (default folder: the workspace) and returns its id. Use when you need a shell the person can watch live in Format's terminal dock.

- changes state · command `terminal.open` · params: `cwd?` string, `cols?` integer, `rows?` integer, `title?` string

### read_terminal

The end of a terminal's output as plain text, colour codes removed. Use after write_terminal, to read what the command printed.

- read-only · command `terminal.read` · params: `id` string, `chars?` integer

### resize_terminal

Resize a terminal Use rarely; the window keeps terminal sizes in step itself.

- changes state · command `terminal.resize` · params: `id` string, `cols` integer, `rows` integer

### restart_terminal

Ends the terminal's shell and starts a fresh one in the same tab and folder; its output so far is cleared. Use when a shell is stuck; the tab stays and its output is cleared.

- changes state · command `terminal.restart` · params: `id` string

### snapshot_terminal

Draws the terminal's current screen, colours included, as a PNG with the native wgpu renderer and returns its path and URL. Needs the native renderer (native.status); useful when a program's screen layout matters more than its text. Use when a program's screen layout matters more than its text; needs the native renderer.

- changes state · command `terminal.snapshot` · params: `id` string

### write_terminal

Types text into a terminal as if at the keyboard. The window shows it live. Use to type a command into a terminal (end it with a newline), then read_terminal.

- changes state · command `terminal.write` · params: `id` string, `data` string

Sets one chat setting: model takes a model id from models.list, effort one of low, medium, high, xhigh, max, permissionMode ask, auto or plan, thinking (show Claude's thinking) true or false, autoCompact (summarize long chats) true or false, compactAt the share of the context window that triggers it, 0.05 to 0.95, webTools (web search and fetch) and workspaceTools (bash and files in the chat's folder) true or false, toolAllow and toolDeny lists of bash, write, edit, agentModel the sub-agents' model id (empty for the chat's model), agentLimit the most sub-agents in one reply, 0 to 10, artifactNetwork (let artifact pages load images and data from the internet) true or false, memory (Claude keeps notes across chats with the memory tool) true or false, outsideAgents (coding agents using Format over MCP) ask, allowed or blocked, sandbox (Claude's bash runs sandboxed: only the chat's folder writable, the home folder hidden) true or false, sandboxNetwork (let sandboxed commands reach the network) true or false, browserTools (Claude can use the built-in browser) true or false, chatEngine (who answers: auto uses the API key when set and otherwise the person's Claude Code sign-in, api, or claude-code) auto, api or claude-code. Use when the person asks for another model, effort, permission mode or tool setting; it applies to all chats.
